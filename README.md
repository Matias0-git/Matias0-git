## 🏛️ What I'm Building: Moducity

**Moducity** manages *expedientes de obras particulares* (building-permit case files) for Argentine municipalities, from the professional's first submission through plan approval (*visado*), inspections and the final certificate of completion. It is in production with the **Municipalidad de Trevelin** and the **Municipalidad de Esquel** (Chubut), with more municipalities on the way.

* **Multi-tenant by design:** one shared platform, with each municipality configuring its own procedures, roles, fees and document templates.
* **Configurable workflows:** different procedure types (new construction, regularization of existing buildings, change of professional, sewer connections) each follow their own approval path.
* **Legally valid digital signatures:** officials sign permits, plan approvals and inspection reports with Argentine *Firma Digital*, including batch signing of plan sheets.
* **Serverless on AWS:** a Next.js front end over Lambda (arm64), DynamoDB, S3, Cognito and Step Functions, all managed as code with Terraform.

## ✨ How I Work

* **Domain first.** Municipal procedures have their own language (*expediente*, *visado*, *refrendo*). I model the software on that language, not the other way around.
* **Business thinking.** Every feature has to save a real official or professional real time.
* **Pragmatic and clean.** Ship small, test it, keep it readable.
* **Built to be trusted.** Least-privilege access, auditable history and legally valid signatures, because public records depend on it.

Concepts I keep coming back to: event-driven architecture · multi-tenancy · domain-driven design · data modelling · infrastructure as code · CI/CD · observability · data quality.
